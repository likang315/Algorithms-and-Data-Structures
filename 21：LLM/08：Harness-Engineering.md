### Harness Engineering

------

[TOC]

##### 01：概述

- Harness 是包裹LLM的运行框架（脚手架），原因是：**系统层面缺乏约束、验证和反馈机制**。
- **Prompt Engineering -> Context Engineering -> Harness Engineering** 演进而来。
  - Prompt Engineering 解决了"说清楚"的问题
  - Context Engineering 解决了"给够信息"的问题
  - Harness Engineering 解决了"系统可靠"的问题
- “Human steer, agents execute”：**人类掌舵，Agent 执行**。

###### Harness Engineering

- **定方向（Steering）**：要知道建什么、为什么建、最终形态是什么
- **搭架子（Harnessing）**：为 Agent 构建可靠的运行框架。
- **做判别（Decision Making）**：关键的架构决策点、技术路线选择点、风险边界节点进行人工干预和确认。

##### 02：生产级的 Harness 所需模块

1. 模型调用层
2. 任务规划层
   - 将复杂的多步骤任务，拆分执行
3. 流程编排层
   - 心跳所在，也叫 ReAct。组装提示词、调用LLM、解析输出、执行工具调用、把结果反馈回去、重复直到完成。
4. 工具
   - 工具是agent的手。它们以schema形式定义（名称、描述、参数类型），注入到LLM的上下文中，让模型知道有哪些可用。
5. 记忆
   - 短期记忆是单次会话内的对话历史，长期记忆跨会话持久化。
   - Anthropic使用CLAUDE.md项目文件和自动生成的MEMORY.md文件管理记忆。
6. 上下文管理
   - 迷失在中间：当关键内容落在窗口中间位置时，模型性能下降超过30%。
   - 生产机策略
     1. 压缩：在接近上限时对对话历史进行摘要。
     2. 即时检索：维护轻量级标识符，动态加载数据。
     3. 子agent委托：每个子agent进行大范围探索，但只返回1000到2000 token的压缩摘要。
7. 提示词构键
   - 组装模型在每一步实际看到的内容，是分层的：系统提示、工具定义、记忆文件、对话历史、当前用户消息。
8. 输出解析
   - Harness检查：有工具调用吗？执行并循环。没有工具调用？那就是最终答案。
9. 状态管理
   - LangGraph 将状态建模为流经图节点的类型字典。
   - Claude Code采用不同的方式：**git提交作为检查点，进度文件作为结构化草稿纸**。
10. 错误处理（四种错误类型）
    - 瞬时错误（带退避重试）
    - LLM可恢复错误（将错误作为ToolMessage返回让模型调整）
    - 用户可修复错误（中断请求人工输入）
    - 意外错误（向上冒泡用于调试）
11. **权限与安全控制**
    - Anthropic在架构上将权限执行与模型推理分离：**模型决定尝试什么，工具系统决定允许什么**。
12. **结果验证与反馈机制**
    - Anthropic推荐三种方式
      1. 基于规则的反馈（测试、代码检查、类型检查器）
      2. 视觉反馈（通过Playwright截图用于UI任务）
      3. LLM作为评判者（独立的子agent评估输出）

##### 03：核心工作流程

- **提示词组装：** Harness构建完整输入：系统提示 + 工具schema + 记忆文件 + 对话历史 + 当前用户消息。
- **LLM推理：** 组装好的提示词发送给模型API，模型生成输出token：文本、工具调用请求，或两者都有。
- **输出解析：** 如果模型只输出文本且没有工具调用，循环结束。如果请求了工具调用，进入执行。如果请求了移交，更新当前agent并重新开始。
- **工具执行：** 对每个工具调用，Harness验证参数、检查权限、在沙盒环境中执行、捕获结果。只读操作可以并发运行；写入操作串行运行。
- **结果检查：** 工具结果被格式化为LLM可读的消息。错误被捕获并作为错误结果返回，让模型可以自我纠正。
- **上下文更新：** 结果追加到对话历史。如果接近上下文窗口限制，Harness触发压缩。
- **循环：** 返回第1步，重复直到终止。

##### 04：主流框架如何实现的

###### Claude Agent SDK

- 通过单一的query()函数暴露Harness，创建agent循环并返回流式消息的异步迭代器。运行时是一个「笨循环」，所有智能住在模型里。
- Claude Code使用收集-行动-验证循环：收集上下文（搜索文件、阅读代码）、采取行动（编辑文件、运行命令）、验证结果（运行测试、检查输出），然后重复。

##### 05：Harness 的演进

- Anthropic 押注于 **薄Harness和模型改进**。
- 基于图的框架押注于显式控制。Anthropic随着**新模型将那些能力内化**，定期从Claude Code的Harness中删除规划步骤。
- Harness不会消失。即使是最强大的模型，也需要某个东西来管理它的上下文窗口、执行它的工具调用、持久化它的状态、以及验证它的工作。
